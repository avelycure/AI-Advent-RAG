# День 22 — сравнение качества RAG

## Условия прогона

- Модель: `deepseek-flash` через официальный DeepSeek Chat Completions API.
- Режим рассуждений отключён: сравнивается обычный ответ модели, а не дополнительный reasoning-бюджет.
- Для каждого режима используется новый пустой чат.
- Температура: `0.2`; максимум ответа: `1200` токенов.
- RAG: локальные embeddings `qwen3-embedding:0.6b`, одинаковый индекс и одинаковый `topK` для всех вопросов.
- Оценка ответа: полнота фактов — 0–2, опора на данные без выдумок — 0–2, корректная ссылка или корректный отказ — 0–1. Максимум — 5.
- Retrieval `hit@K` отмечается отдельно: ожидаемый файл должен оказаться среди фактически отправленных источников.

Ожидания и источники заранее зафиксированы в `eval/day22-control-questions.json`. Воспроизводимый прогон запускается командой:

```bash
DEEPSEEK_API_KEY=... npm run eval:day22 -- "/path/to/vault" --confirm-send-notes
```

Флаг `--confirm-send-notes` обязателен, потому что RAG-прогон отправляет найденные фрагменты тестовых заметок в DeepSeek. Полные ответы и фактически отправленные источники записаны в `eval/day22-results.json`.

## Итог

- Без RAG: **29/50**.
- С RAG: **49/50**.
- Положительный retrieval `hit@10`: **9/9 (100%)**.
- Отрицательный контроль: **0/1** — поиск всегда возвращает `topK` чанков и пока не применяет порог релевантности.

RAG заметно улучшил ответы на вопросы о личных впечатлениях, реальном рецепте и
конспектах тренировок. Основные следующие улучшения: порог минимальной близости или
reranker для отрицательных запросов, а также более строгая инструкция отвечать без
служебной самопроверки и перечисления нерелевантных источников.
