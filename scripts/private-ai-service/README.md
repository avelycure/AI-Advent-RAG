# День 30. Локальная LLM как приватный сервис

Отдельный демонстрационный сервис для домашней сети: Node.js HTTP API → локальная Ollama → Qwen. Не использует код плагина, не меняет его настройки и не запускается вместе с Obsidian. Нет VPS, туннеля, внешних библиотек, CDN или облачной модели.

## Запуск

Нужны Node.js 22+ и работающая Ollama с установленной `qwen3.8:27b`. Ollama остаётся на `127.0.0.1:11434`; её адрес и настройки не изменяются.

Из корня репозитория:

```sh
node scripts/private-ai-service/server.mjs
```

Сервис автоматически выбирает частный IPv4-адрес компьютера и порт 8787. При отсутствии домашнего сетевого адреса использует `127.0.0.1`. Для выбора конкретного адреса:

```sh
PRIVATE_AI_HOST=192.168.0.135 PRIVATE_AI_PORT=8787 node scripts/private-ai-service/server.mjs
```

Адрес выводится в терминал. Откройте его в браузере на этом компьютере или другом устройстве той же домашней сети. Вставьте ключ из `scripts/private-ai-service/.local/api-key.txt` и нажмите «Подключиться». Файл создаётся при первом запуске с правами `0600` в каталоге `0700`, исключён из Git. Ключ не входит в URL, код страницы или логи. В браузере хранится только в памяти вкладки; после обновления потребуется ввести снова.

Остановка — `Ctrl+C` в терминале сервера. Повторный запуск использует тот же ключ. Для ротации остановите сервер, удалите локальный файл ключа и запустите снова. Автозапуск не устанавливается. Чат и история не сохраняются на диск.

HTTP рассчитан на доверенную домашнюю сеть: содержимое и ключ передаются без TLS. Сервис привязывается к выбранному частному адресу, не к `0.0.0.0`; доступность с другого устройства также зависит от Wi-Fi isolation и firewall. Маршрутизацию портов и публикацию в Интернет этот проект не настраивает.

## API

`GET /` — веб-чат. `GET /api/status` — модель, очередь, счётчики и ограничения. `POST /api/chat` — потоковый чат в формате NDJSON. API требует `Authorization: Bearer <ключ>`; CORS не включён, запросы браузера с другого origin отклоняются.

Пример клиента из корня репозитория (ключ читается из файла без вывода):

```sh
node --input-type=module <<'JS'
import { readFile } from 'node:fs/promises';
const key = (await readFile('scripts/private-ai-service/.local/api-key.txt', 'utf8')).trim();
const response = await fetch('http://192.168.0.135:8787/api/chat', {
  method: 'POST',
  headers: { Authorization: `Bearer ${key}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({
    messages: [{ role: 'user', content: 'Что такое локальная LLM? Ответь кратко.' }],
    num_ctx: 8192,
    max_tokens: 128,
    temperature: 0.2,
  }),
});
for await (const chunk of response.body) process.stdout.write(chunk);
JS
```

В примере замените IP на адрес, напечатанный сервером. История передаётся клиентом в `messages`; роли — `user` и `assistant`, последнее сообщение — `user`. Поле `model` клиент не выбирает. `system`, инструменты и произвольные опции Ollama через API не принимаются.

Поток состоит из событий:

- `status`: `queued` с позицией начиная с 1 или `running` с позицией 0;
- `delta`: фрагмент ответа в поле `text`;
- `done`: завершение, модель, метрики; `truncated: true` означает достижение лимита длины;
- `error`: ошибка генерации после открытия потока.

HTTP 200 означает принятие запроса, а успешное завершение подтверждает только событие `done`. До открытия потока ошибки возвращаются JSON: 400 — параметры, 401 — ключ, 403 — origin, 413 — вход, 415 — Content-Type, 429 — частота с Retry-After, 503 — очередь. Метрики: время ожидания, обработки и первого токена, токены и скорость генерации. Время обработки включает проверку модели и загрузку; скорость рассчитывается по `eval_count / eval_duration` Ollama.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Одновременно в модели | 1 запрос |
| Ожидающих запросов | До 8, FIFO |
| Частота | 3 попытки POST /api/chat за 60 секунд, общий лимит ключа |
| Контекст `num_ctx` | 4096–8192 токена |
| Ответ `max_tokens` | 1–1024 токена |
| Температура | 0–1, по умолчанию 0.2 |
| История | 1–20 сообщений |
| Текст сообщений | До 4096 байт UTF-8 суммарно, при меньшем контексте лимит уменьшается |
| JSON-запрос | До 32 КиБ |
| Таймаут активного запроса | 180 секунд |

Байтный лимит — консервативная проверка входа до обращения к модели, а не измерение токенизатором. Дополнительно резервируется место под ответ и шаблон сообщений; `num_ctx` ограничивает окно Ollama. Текст не обрезается автоматически: слишком длинный диалог требует нового разговора. Все клиенты этого сервиса используют общую очередь. Прямые запросы Obsidian к Ollama обходят её — для чистого испытания не запускайте генерацию в плагине одновременно.

Отмена закрывает HTTP-запрос к Ollama; ожидающая задача удаляется из очереди. Ошибка или таймаут освобождает очередь. Модели с признаками облачного backend отклоняются через `/api/show`. После запроса Qwen остаётся загруженной до 2 минут; автоматическое принудительное завершение Ollama не выполняется.

## Проверка

```sh
node --test scripts/private-ai-service/checks.mjs
node scripts/private-ai-service/smoke.mjs
```

Первый запуск проверяет реальный HTTP-сервер с управляемой имитацией Ollama: авторизацию, origin, FIFO и отсутствие параллельной генерации, очередь, rate limit и восстановление окна, контекст, вход, выход, облачный запрет, отмену, таймаут, восстановление после ошибки.

Второй требует запущенного сервиса и настоящей Qwen, делает 3 одновременных коротких запроса по LAN-адресу и сохраняет `reports/real-qwen.json`. Не содержит API-ключей. При повторных прогонах учитывайте общий rate limit. При лимите 3 проверка автоматически ждёт 61 секунду между проверкой входа и тремя запросами к Qwen. Старый отчёт real-qwen.json относится к прогону с лимитом 10.

Фактический прогон 11 октября 2026: 3/3 ответа завершены. Обработка заняла 1.88 / 1.76 / 2.20 с, ожидание 0.00 / 1.88 / 3.64 с (модель уже была загружена). Ответы: «Привет», «4», «Париж». Также проверены 401 без ключа, 400 при num_ctx=16384, 413 при большом входе и 429 с Retry-After после исчерпания лимита. Веб-чат проверен через браузер, Qwen ответила «Рим». Отдельные HTTP-тесты: 9/9 прошли.

LAN-проверка выполнена с того же Mac по его сетевому IP, не с отдельного устройства. Для завершения сетевого демо откройте напечатанный URL на телефоне в той же Wi-Fi сети, введите ключ и отправьте сообщение. После сна компьютера или смены сетевого адреса сервер может потребовать перезапуска.

Основа API Ollama: https://docs.ollama.com/api/chat и https://docs.ollama.com/api/ps.
